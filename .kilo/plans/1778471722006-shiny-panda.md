# Debug Window Modernization Plan — Catppuccin Mocha Theme

## Executive Summary
**Current State**: DebugWndProc (lines 677–731) uses immediate-mode GDI drawing with solid brushes, no double-buffering, standard rectangular buttons, and per-paint font creation. Fully functional but Windows 95 aesthetic.

**Target**: Modern dark theme with Catppuccin Mocha colors, rounded corners, smooth rendering, Segoe UI typography — **zero functionality changes**.

**Recommended Architecture**: **Keep "Fake Controls" (owner-draw rectangles)**. The window already uses this pattern (RECT hitboxes + manual WM_PAINT). No need to introduce standard BUTTON/STATIC controls, which would require subclassing or complex owner-draw messages (WM_DRAWITEM) and would complicate the existing clean logic.

---

## Phase 1 — Double Buffering (Flicker Elimination)
**Goal**: Eliminate all flicker during repaints.

**Implementation**:
1. In `WM_PAINT`: BeginPaint → CreateCompatibleDC → CreateCompatibleBitmap → SelectObject → paint to memory DC → BitBlt to window DC → cleanup.
2. Use `ps.rcPaint` to only redraw dirty region (optional optimization).
3. Do NOT use `ValidateRect` or `CS_HREDRAW/CS_VREDRAW` class styles — keep default.

**Validation**: Toggle `g_bindingMode` rapidly, resize window — no flicker should be visible.

---

## Phase 2 — Font Management (Lifetime & Efficiency)
**Goal**: Stop creating/deleting fonts on every paint.

**Implementation**:
1. Add global or static HFONT variables: `hFontBtn` (Segoe UI 12–14pt, bold/normal), `hFontDebug` (Consolas 13pt, unchanged).
2. In `WM_CREATE`: `CreateFontW()` once; store handles.
3. In `WM_PAINT`: `SelectObject()` the pre-created fonts; **do not delete**.
4. In `WM_DESTROY`: `DeleteObject()` all created fonts.

**Note**: Segoe UI is guaranteed present on Windows 10+. Use `FW_NORMAL` for normal state, `FW_BOLD` for button labels. Keep `DEFAULT_CHARSET`, `OUT_DEFAULT_PRECIS`.

## Phase 4 — Rounded Corners (GDI RoundRect / Path2)
**Goal**: Buttons with 6–8px radius.

**Two safe approaches** (pick one):

### Option A — RoundRect (simplest, pure GDI)
```cpp
HRGN hRgn = CreateRoundRectRgn(left, top, right, bottom, radius, radius);
FillRgn(hdcMem, hRgn, hBrush);
DeleteObject(hRgn);
```
Or call `RoundRect(hdcMem, left, top, right, bottom, radius, radius)` directly with a brush selected.

**Pros**: Minimal code, no GDI+ initialization.  
**Cons**: Anti-aliasing is poor (jagged on low DPI).

### Option B — GDI+ (slightly better quality)
1. Link `gdiplus.lib`, include `<gdiplus.h>`.
2. `GdiplusStartup()` once in `WinMain` (before any window creation).
3. In `WM_PAINT`: use `Graphics` from the memory HDC, `SolidBrush`, `FillRoundedRectangle` (via `GraphicsPath` + `AddArc` + `AddLine`).
4. `GdiplusShutdown()` in `WM_DESTROY` of the main window (or at process exit).

**Pros**: Smooth anti-aliased curves.  
**Cons**: Adds a lightweight dependency (GDI+ is always present on Windows). Startup cost negligible.

**Recommendation**: **Start with Option A (RoundRect)**. It's simpler and fully adequate for small UI elements. Upgrade to GDI+ only if visual quality is unsatisfactory.

## Phase 5 — Hover & State Feedback (Optional Polish)
**Goal**: Visual feedback when mouse is over a button.

**Implementation**:
1. Add `bool g_btnBindHover = false;`, `bool g_btnPanHover = false;` globals.
2. Track via `WM_MOUSEMOVE` in `DebugWndProc`:
   ```cpp
   case WM_MOUSEMOVE: {
       POINT pt = { LOWORD(lParam), HIWORD(lParam) };
       bool inBind = PtInRect(&g_btnBindRect, pt);
       bool inPan  = PtInRect(&g_btnPanRect,  pt);
       if (inBind != g_btnBindHover || inPan != g_btnPanHover) {
           g_btnBindHover = inBind; g_btnPanHover = inPan;
           InvalidateRect(hwnd, NULL, FALSE);  // repaint
       }
       return 0;
   }
   ```
3. In `WM_PAINT`: Choose button fill color based on `(g_bindingMode ? CLR_BIND : (hover ? CLR_HOT : CLR_NORM))`.

**No risk** — purely visual, does not affect click logic.

## Top 3 Risks & Mitigations

| # | Risk | Impact | Mitigation |
|---|------|--------|------------|
| 1 | **GDI resource leak** — forgetting `DeleteObject()` or `DeleteDC()` | Process GDI handle count grows → eventually fails to create DC/bitmap → blank window or crash | Use RAII wrappers locally; after each WM_PAINT, log `GetObjectType()` counts in debug; ensure every `Create*` has matching `DeleteObject` in all code paths (including early returns) |
| 2 | **Flicker persists** — double-buffering implemented incorrectly (e.g., BitBlt before drawing completes) |用户体验严重受损 | Test on high-DPI monitor; ensure BitBlt uses `SRCCOPY`; validate bitmap selected into mem DC before drawing; use `ps.rcPaint` to limit redraw region |
| 3 | **Button hit detection breaks** — changing button shape to rounded but leaving RECT hitbox | Clicking corners registers miss even though visual seems clickable | Decide: keep rectangular hitbox (simpler, acceptable) OR implement `PtInRegion` with rounded region. **Recommend keeping rectangular hitbox** for safety; visual rounding is cosmetic only. |

## Code Structure Changes (Summary)

**New globals** (above `DebugWndProc`):
```cpp
HFONT g_hFontBtn = NULL;
HFONT g_hFontDebug = NULL;
bool  g_btnBindHover = false;
bool g_btnPanHover = false;
```

**WM_CREATE**:
- Create both fonts; store in globals.

**WM_SIZE**:
- Unchanged (RECT calculation stays).
- Consider increasing button height to 50px for better touch/clickability.

**WM_MOUSEMOVE** (new):
- Update hover flags; InvalidateRect on change.

**WM_PAINT**:
- Classic double-buffered pattern:
  ```cpp
  PAINTSTRUCT ps; HDC hdc = BeginPaint(hwnd, &ps);
  HDC mem = CreateCompatibleDC(hdc);
  HBITMAP bmp = CreateCompatibleBitmap(hdc, rc.right, rc.bottom);
  HBITMAP oldBmp = (HBITMAP)SelectObject(mem, bmp);
  // — draw background, rounded buttons, text to mem —
  BitBlt(hdc, 0, 0, rc.right, rc.bottom, mem, 0, 0, SRCCOPY);
  // — cleanup —
  SelectObject(mem, oldBmp); DeleteObject(bmp); DeleteDC(mem);
  EndPaint(hwnd, &ps);
  ```

**WM_DESTROY**:
- Delete fonts (if created).
